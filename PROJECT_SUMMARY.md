# Telegram-приложение «Траты»: резюме для передачи

Дата: 03.11.2026. Владелец: vovaod187 (GitHub), бот `@expensesforvovibot` (https://t.me/expensesforvovibot).
Репозиторий: https://github.com/vovaod187/expenses-app (публичный).

## 1. Что умеет приложение

Telegram Mini App для личного учёта трат. Изначально им пользовался только владелец, теперь доработано до многопользовательской версии.

- **Ввод** траты: сумма (запятая или точка), категория, комментарий (до 200 символов), дата.
- **Итоги**: суммы по категориям за текущую неделю и месяц.
- **Архив**: итоги прошлых недель и месяцев (последние 12 периодов).
- **Отчёты в Telegram**: каждому пользователю в личный чат. Недельный (понедельник, 9:00) и месячный (1-е число, 9:00): всего, по категориям, главная категория, сравнение с прошлым периодом.
- **Мультипользовательность**: регистрация по одноразовому инвайт-коду, у каждого своя таблица, вкладка «Админ» только у владельца (создать инвайт, список пользователей, отключить/включить).
- Категории общие для всех, единый список `ALLOWED` в `Code.gs` (приложение получает его в `whoami`): Продукты, Кафе и доставка, Транспорт, Жилье, Шопинг, Спорт, Подписки, Развлечения, Учеба, Прочее. Старое «Еда» засчитывается в «Продукты» через `ALIASES`. В Итогах и Архиве нулевые категории скрыты.

## 2. Стек

| Слой | Технология |
|---|---|
| Фронтенд | Один файл `index.html` (чистый HTML/CSS/JS, без сборки и фреймворков), Telegram WebApp SDK |
| Хостинг фронтенда | GitHub (страница, подключённая к боту) |
| Бэкенд | Google Apps Script, веб-приложение (`doPost`), файл `Code.gs` |
| Данные | Google Таблицы + Google Диск |
| Уведомления | Telegram Bot API (`sendMessage` через `UrlFetchApp`) |
| Секреты | Свойства скрипта: `BOT_TOKEN`, `OWNER_ID`, `FOLDER_ID` (создаётся автоматически) |

Запросы: фронтенд шлёт `POST` на адрес `/exec` с `Content-Type: text/plain` (чтобы не было preflight-запроса) и телом JSON `{action, initData, ...}`.

Безопасность: каждый запрос проверяется по подписи Telegram (`verify_`, HMAC-SHA256, срок `auth_date` 24 часа). Комментарии защищены от формул (экранирование `= + - @` в начале). Вывод во фронтенде через `textContent`.

## 3. Структура данных

### Главная таблица (к ней привязан скрипт)
Это одновременно **таблица владельца** и **реестр**.

| Лист | Назначение |
|---|---|
| `Траты` | Траты владельца: Дата, Сумма, Категория, Комментарий |
| `Архив` | Архив владельца: Тип (Неделя/Месяц), Начало (текст `yyyy-MM-dd`), Категория, Сумма |
| `Итоги` | Лист владельца (был до доработки, скриптом не используется) |
| `_Users` | Реестр: `telegram_id`, `имя`, `spreadsheet_id`, `статус` (active/disabled), `дата регистрации` |
| `_Invites` | Инвайты: `код`, `создан`, `истекает`, `использован кем`, `когда` |

### Лист «Настройки» в таблице пользователя
Ключ | Значение: `budget:month`, `limit:week:<категория>`, `limit:month:<категория>`, `notified:<week|month>:<ключ периода>:<категория>` (уведомление о 80% уже отправлено). В листе «Траты» колонка E «Кто» (имя того, кто записал).

### Таблица каждого пользователя
Создаётся скриптом автоматически при регистрации: «Траты - Имя (@ник)», лежит на Google Диске **владельца** в папке «Траты: пользователи». Листы `Траты` и `Архив` с такой же структурой, как у владельца.

Владелец записан в `_Users` как первый пользователь (`spreadsheet_id` = главная таблица).


### Общий бюджет (этап 3)
Два пользователя в `_Users` с одинаковым `spreadsheet_id` ведут одну таблицу. Код партнёра создаёт сам пользователь (Настройки → Общий бюджет): строка в `_Invites` с типом `partner`, ID таблицы и ID пригласившего (колонки F–H). Новый человек вводит код при регистрации (таблица не создаётся), уже зарегистрированный — в настройках (`joinPartner`, его старая таблица остаётся на Диске). Максимум двое. При подключении старые траты без «Кто» подписываются именем пригласившего. `leavePartner`: уходящий получает новую пустую таблицу, общие траты остаются у партнёра. Лимиты, бюджет, уведомления о 80% и отчёты общие (приходят обоим). В итогах блок «Кто сколько внёс» (`summary.byWho`), в истории имя внёсшего. Функции включаются при `whoami.version >= 3`.

### Напоминание и серия (этап 4)
`sendReminders` по триггеру каждый день около 21:00 (создаётся один раз функцией `setupReminderTrigger`): пишет тем, у кого в таблице за сегодня нет трат (в общем бюджете хватает записи одного). Выключается каждым в Настройках, хранится в `_Users`, колонка F (`off`). Серия (`summary.streak`) — дней подряд с тратами; если сегодня пусто, считается по вчера. На главной значок «🔥 N дней подряд» от 2 дней, конфетти на 3, 7, 14, 30, 50, 100, 200, 365. `summary_` читает лист «Траты» один раз. Функции включаются при `whoami.version >= 4`.

### Валюты (этап 5)
Ввод в BYN, USD, EUR, PLN, AMD (`CURRENCIES`). Сумма пересчитывается в BYN по официальному курсу Нацбанка РБ на дату траты через Frankfurter (открытое зеркало курсов НБРБ): `https://api.frankfurter.dev/v2/rate/<КОД>/BYN?date=yyyy-MM-dd&providers=nbrb`, поле `rate` = BYN за 1 единицу. Сайт НБРБ напрямую с серверов Google не отвечает (проверено `testRates` 13.11.2026), поэтому не используется. Если Frankfurter не ответил, 30 минут к нему не обращаемся (`down_frankfurter` в кэше). Проверка вручную: функция `testRates` (журнал выполнения). Нет курса на дату (выходные) — берётся ближайший предыдущий, до 7 дней; будущая дата — курс на сегодня; курсы кэшируются на 6 часов. Нацбанк недоступен — ошибка `rate_unavailable`, трата не пишется (в BYN писать можно). В листе «Траты»: B — сумма в BYN (по ней все итоги, лимиты, отчёты), F «Валюта», G «Сумма в валюте» (для BYN пусто). В приложении: валюты кнопками под суммой, предпросмотр «≈ X BYN» (действие `rates`), в списках под суммой исходная сумма в валюте; последняя валюта запоминается на 12 часов. Включается при `whoami.version >= 5`.

### Итоги года (этап 6)
`yearRecap_(ss, year)`: сумма и число трат, дней с записями, в среднем в день, категории по убыванию, самый дорогой месяц и день, самая крупная трата, самая длинная серия, «чаще всего» (комментарий, встречающийся от 3 раз, без учёта регистра), траты в валюте, кто сколько внёс, сумма за прошлый год. `sendYearRecaps` по триггеру 31-го числа около 12:00 (создаётся один раз `setupYearTrigger`), отправляет только 31 декабря, всем активным пользователям с тратами за год. В приложении: кнопка «Мой <год> год» в Итогах (всегда; пока год идёт — данные на сегодня), баннер на главной с 20 декабря по 15 января (в январе — прошлый год), просмотр карточками (тап справа — дальше, слева — назад), «Поделиться» через Telegram. Включается при `whoami.version >= 6`.

## 4. Ключевые файлы и функции

Файлы: `Code.gs` (бэкенд, ~520 строк), `index.html` (фронтенд, ~350 строк), `DEPLOY.md` (инструкция запуска), `PROJECT_SUMMARY.md` (этот файл).

### `Code.gs`
- **Вход:** `doPost(e)`. Действия: `whoami`, `register` (доступны без регистрации); `add`, `summary`, `archive`, `history`, `update`, `delete`, `setLimit`, `setBudget`, `partnerInvite`, `joinPartner`, `leavePartner`, `setReminder`, `rates`, `yearRecap` (обычные); `createInvite`, `listUsers`, `setUserStatus` (только `OWNER_ID`).
- **Коды ошибок:** `denied`, `not_registered`, `disabled`, `bad_invite`, `too_many_attempts`, `bad_email`, `create_failed`, `no_access_to_sheet`, `already_registered`, `cannot_change_owner`, `no_such_user`, `bad data`, `server error`.
- **Реестр:** `usersSheet_`, `invitesSheet_`, `allUsers_`, `getUser_`, `userSs_` (открывает таблицу пользователя), `displayName_`, `visible_` (определяет невидимые имена).
- **Регистрация:** `register_` (проверка инвайта, лимит 5 неудачных попыток в час через `CacheService`, `LockService`), `createUserSheet_`, `usersFolder_`, `ensureSheets_`. Если указана почта, выдаётся доступ на просмотр (`addViewer`); при неудаче регистрация всё равно проходит.
- **Админ:** `createInvite_` (10 символов без похожих, 7 дней), `listUsers_`, `setUserStatus_`.
- **Траты:** `add_`, `sumByCategory_`, `summary_`, `archive_` (без дублей при повторе), `archiveList_`, `weekStart_`.
- **По расписанию:** `forEachActiveUser_` (ошибка у одного не останавливает остальных), `archiveWeek`, `archiveMonth`, `sendWeeklyReport`, `sendMonthlyReport`, `report_`, `sendMessage_`.
- **Разовые запуски вручную:** `setupMulti` (создаёт реестр и записывает владельца), `setupTriggers`, `setupReportTriggers`.

### `index.html`
Дизайн «Сумерки» (тёмный фон, фиолетовый акцент, цифры шрифтом Lora, текст Inter из Google Fonts). Нижняя панель: Главная, Итоги, кнопка «+», История, Настройки. Главная: кольцо (доля прошедших дней месяца) с суммой за месяц, сумма за неделю, 3 последние траты. «+» открывает лист ввода: крупная сумма, плитки категорий с эмодзи (запоминается последняя), комментарий и дата под «Комментарий и дата». Итоги: неделя/месяц, кольцевая диаграмма, список по убыванию, архив прошлых периодов. История: траты месяца по дням; нажатие открывает правку (сохранить или удалить в два нажатия). Главная с бюджетом показывает «Можно потратить сегодня»: (бюджет − потрачено до сегодня) / оставшиеся дни − потрачено сегодня. Итоги показывают полоски лимитов (жёлтая от 80%, красная при превышении). Настройки: бюджет на месяц и лимиты по категориям на неделю/месяц. Новые функции включаются только если whoami вернул version >= 2 (старый сервер принял бы неизвестное действие за запись траты). Настройки: имя, про отчёты; для владельца админка (инвайты, пользователи). Регистрация, Telegram BackButton и вибрация. Со старым бэкендом (без `history`) история просто скрывается.

## 5. Как запускается и деплоится

1. Apps Script: заменить код на `Code.gs`, сохранить.
2. Один раз запустить `setupMulti` и разрешить новые права (таблицы, Google Диск).
3. **Не запускать повторно** `setupTriggers` и `setupReportTriggers` (будут дубли). Текущие четыре триггера уже есть: `archiveWeek`, `archiveMonth`, `sendWeeklyReport`, `sendMonthlyReport`. Имена функций не менялись, поэтому триггеры сами работают на всех пользователей.
4. Deploy, Manage deployments, карандаш, **New version**, Deploy. Адрес `/exec` остаётся прежним (он прописан в `URL_API` внутри `index.html`).
5. `index.html` заменить в репозитории на GitHub.

Добавление человека: вкладка «Админ», «Создать инвайт-код», отправить код и текст-приглашение (в нём ссылка на бота, нажать Start, ввести код).

## 6. Что уже решено

- Остаёмся на Apps Script и Google Таблицах, переход на Python/SQL нецелесообразен (нужен свой сервер, при этом теряется «таблица для каждого»). Пересматривать при росте свыше 30–50 пользователей.
- Хранение: у каждого пользователя своя таблица; изначально обсуждался вариант «пользователь сам создаёт таблицу», затем выбран **автосоздание на Диске владельца**.
- Добавление людей: только инвайт-код, одноразовый, 7 дней.
- Отчёты и архив: каждому по его данным.
- Категории: общие, зашиты в код.
- Доступ к таблице для пользователя: по желанию, только на просмотр, по указанной при регистрации почте.
- Пользователей честно предупреждать: таблицы лежат на Диске владельца, он технически видит все данные.

## 7. Что проверено, а что нет

- Бэкенд проверен автотестами на **имитации** Google-сервисов (регистрация, изоляция данных между пользователями, отчёты, отключение, лимит попыток, невидимые имена): 43 проверки прошли.
- Фронтенд проверен только на синтаксис, в браузере и в Telegram не запускался.
- В реальном Google и Telegram многопользовательская версия подтверждена частично: владелец видел вкладку «Админ» и зарегистрированного пользователя, но имя пользователя отображалось пустым (в код добавлено исправление, подтверждения, что оно сработало, пока нет). Основной сценарий (запись траты, итоги, отчёт у второго человека) полностью не подтверждён.

## 8. Что осталось доработать / открытые вопросы

1. **Подтвердить работу в реальных условиях:** развернуть новую версию, проверить регистрацию живого человека, запись траты, итоги и первый отчёт. Через неделю проверить колонку «Частота появления ошибок» у триггеров (должно быть 0%).
2. **Пустое имя в админке** у одного из пользователей: после обновления кода проверить. Если осталось, смотреть лист `_Users`, колонка B (формула `=LEN(B3)`). Можно вписать имя вручную.
3. **Почту нельзя добавить после регистрации.** Если человек не указал её сразу, доступ к его таблице владелец выдаёт вручную на Диске. Идея: действие `setEmail` и поле в приложении.
4. **Часовой пояс:** один для всех (пояс скрипта). Людям из других часовых поясов отчёты приходят в неудобное время, даты «сегодня» могут сбиваться.
5. **Отчёты только тем, кто нажал Start у бота.** Ошибки отправки пишутся только в журнал. Можно показывать это в админке.
6. **Лимит 6 минут** на выполнение скрипта: для десятка пользователей запас большой, при росте цикл `forEachActiveUser_` надо разбивать.
7. **Нет удаления пользователя и его данных** (только «отключить»). Нет редактирования и удаления трат из приложения.
8. **Своих категорий у пользователей нет** (решено оставить общие, но может понадобиться).
9. **Лист «Итоги»** в главной таблице скриптом не используется, статус неясен (проверить, нужен ли).
10. **Коммит в GitHub:** изменения лежат только в рабочей копии (`index.html` изменён, `Code.gs`, `DEPLOY.md`, `PROJECT_SUMMARY.md` новые). Доступ на запись у Claude в репозиторий не настроен, владелец заливает файлы вручную.
11. **Секреты:** `BOT_TOKEN` хранится в свойствах скрипта, в репозиторий не попадает. Адрес `/exec` в `index.html` открытый, это нормально, защита идёт через подпись Telegram.
